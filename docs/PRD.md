# PRD: simple-tetris 拡張

| | |

## Objective

最小構成で実装済みの simple-tetris を、「遊べる完成度のテトリス」へ拡張する。成功の定義:

- P0 の全機能が実装・マージされ、CI (build + test) が green であること
- 追加機能によって既存のコアループ (移動/回転/ドロップ/ライン消去/ゲームオーバー/Restart) にリグレッションが無いこと
- ランタイム依存を react / react-dom のみに保ったまま実現すること

## Background / Context

simple-tetris は React 19 + Vite + TypeScript による最小テトリス。コアループは実装・検証済みで、以下の意図的制約が残っている:

- ミノ出現は完全ランダム (bag 方式でないため同一ミノが連続しうる)
- 回転補正 (壁キック) なし。壁際では回転が拒否される
- 落下速度は 500ms 固定 (レベル概念なし)
- スコアは 100×n² の簡易式。ハイスコアの保存なし
- ネクスト表示・ホールド・ゴースト・ポーズ・効果音なし

コードベースは 3 層構成: `src/game/` (React 非依存の純粋ロジック) / `src/hooks/` (状態管理・入力・タイマー) / `src/components/` (表示 + CSS)。vitest によるロジック層ユニットテストと GitHub Actions CI が整備済み。

想定ユーザーはカジュアルにブラウザでテトリスを遊ぶ個人 (キーボード操作の PC 利用が主、P2 でモバイルにも拡大)。

## Success Metrics

分析基盤を持たない小規模プロダクトのため、計測可能な代理指標で判定する:

- **機能完了数**: P0 5 件のマージ数 (目標: 5/5)。P1 以降は上積み
- **品質**: 全 PR で CI (build + vitest) green。意図しない既存挙動の破壊ゼロ (本 PRD が許可する挙動変更に伴うテスト更新はリグレッションとしない)
- **プレイ検証**: 各機能の Launch Checklist (後述) を実機で全項目パスすること

## Non-goals (スコープ外)

- オンライン対戦・マルチプレイヤー・サーバーサイド機能
- アカウント・ランキング共有等の外部サービス連携
- ランタイムライブラリの追加 (状態管理・アニメーション・サウンド等はすべて Web 標準 API + React で実現する)
- 収益化・広告・アナリティクス計測基盤
- ネイティブアプリ化 (PWA (#19) までをスコープとする)

## Requirements

優先度は Google の P0–P4 に準拠する (本 PRD では P0–P2 のみ使用):

| 優先度 | 意味 |
|--------|------|
| **P0** | Must。最優先で実装する。プレイ体験への影響が大きく、独立性が高く、規模が小〜中 |
| **P1** | Should。P0 の後に着手する。体験向上は明確だが根幹ではない (演出・周辺機能) |
| **P2** | Could。余裕があれば。規模が大きい・複数機能が絡む・対象が限定的 |

規模: S (小: 数十行) / M (中: 1〜数ファイル追加) / L (大: 複数機能が相互依存)。

### P0 の要件詳細

#### 1. ネクスト表示 + 7-bag

ミノ出現を「7 種を 1 巡ずつシャッフルして配る」bag 方式にし、次のミノを表示する。

- 出現順は 7-bag 方式 (7 種を各 1 個含む bag をシャッフルして順に配り、使い切ったら次の bag を生成する。これにより同一種の連続出現は bag 境界での最大 2 回、同一種の出現間隔は最大 12 手に収まる)
- 盤面の横に次の 1 ミノ以上をプレビュー表示する (最大 5 手までは任意)
- Restart で bag とプレビューもリセットされる

#### 2. ゴーストピース

ハードドロップの着地位置を盤面上に半透明表示する。

- 現在ミノの真下方向の着地位置に、区別できる見た目 (半透明・輪郭等) で表示する
- 移動・回転に追従する。現在ミノと重なる場合は現在ミノの描画を優先する

#### 3. レベル制・落下速度上昇 (スタッツ表示含む)

消去ライン数の累計でレベルが上がり、自動落下間隔が短くなる。

- レベル = floor(累計消去ライン数 ÷ 10) + 1 を既定式とする
- 落下間隔 = max(100, 500 − (レベル − 1) × 50) ms を既定式とする (係数の調整は可。単調減少と下限 100ms は必須)
- スコアと並べてレベル・累計ライン数を表示する (配置は UX / Mockups の左パネル合意に従う)
- Restart でレベル・ライン数もリセットされる

#### 4. ポーズ

プレイを一時停止できる。

- P または Esc キーで一時停止/再開をトグルする
- 一時停止中は自動落下と、再開操作を除くゲームプレイ入力が止まり、一時停止中であることが視覚的にわかる
- 一時停止中に盤面が見え続けるかどうかは実装判断に委ねる (先読み防止で隠す選択も可)

#### 5. ハイスコア保存

ベストスコアを localStorage に保存し表示する。

- ゲームオーバー時、スコアがベストを上回っていれば保存する
- 現在スコアと並べてベストスコアを常時表示する (配置は UX / Mockups の左パネル合意に従う)
- localStorage が使えない環境でもゲーム自体は動作する (保存だけ無効化)

### P1 の要件詳細

#### 6. ホールド

現在のミノを 1 枠に取り置きし、後で交換できる。

- 専用キー (例: C / Shift) で現在ミノをホールド枠へ移し、枠にミノがあれば交換する
- ホールド枠が空の状態でホールドした場合は、#1 のネクストキュー先頭を次のアクティブミノとしてキューを進める (独立生成しない — ネクスト表示・7-bag の決定性を保つため)
- 同一ミノの連続ホールドは 1 回のロックまで不可 (標準ルール)
- ホールド枠を盤面の横に表示する

#### 7. ライン消去・ドロップの演出

消去とハードドロップに視覚フィードバックを付ける。

- ライン消去時に対象行が視認できる演出 (フラッシュ・フェード等) を入れる
- ハードドロップ時に着地が視認できる短い演出を入れる
- 演出中も入力を受け付ける (演出待ちで入力をブロックしない)
- CSS transition/animation で実現する (ライブラリ不可)

#### 8. 効果音

主要イベントに効果音を付ける。

- 対象: 移動/回転、ハードドロップ、ライン消去、ゲームオーバー (最低限この 4 種)
- Web Audio API で実装する (音源ファイル同梱または合成音。ライブラリ不可)
- ミュートトグルを設け、設定を localStorage に保存する

#### 9. テーマ切替

配色テーマを切り替えられる。

- 最低 2 テーマ (現行ダーク + ライト等) をトグルで切替できる
- ミノ色・盤面色・背景色がテーマに追従する (CSS カスタムプロパティ化を想定)
- 選択テーマを localStorage に保存する

#### 10. Game Over 演出改善

ゲームオーバー時の見た目を整える。

- 天井で衝突したスポーンミノが盤面に重なって見える既知の見た目を解消する (盤面スナップショット固定等)
- ゲームオーバーの視覚演出 (盤面のグレーアウト等) を加えてよい
- 既存の「over 中は Space が Restart ボタンのネイティブ操作に渡る」挙動を壊さない

#### 11. デプロイ (GitHub Pages)

ビルド成果物を GitHub Pages で公開する。

- main への push で CI からデプロイされる
- Vite の `base` 設定等、Pages のサブパス配信で動作すること
- README に公開 URL を記載する

### P2 の要件詳細

#### 12. SRS 壁キック + ロックディレイ + T-スピン

回転まわりを本家準拠に引き上げる。**3 点は仕様が相互依存するため 1 まとまりで実装する。**

- SRS 準拠の壁キック (回転が壁・床・既存ブロックで拒否される場合にオフセット候補を試す)
- ロックディレイ: 接地後一定時間 (例: 500ms) は移動・回転を受け付け、その間は固定しない (無限延長はしない。リセット回数上限は任意)
- T-スピン判定 (3-corner 方式) を実装し、判定結果 (T-Spin Single/Double/Triple) を #13 が参照できる形で公開する。**スコア加点は #13 の所掌で、本項ではスコアを変更しない**
- 壁キック導入で回転の期待挙動が変わる場合、既存テストの期待値は本要件に合わせて更新してよい (Launch Checklist の許可条項に従う)。キック・T-スピン判定のテストを同 PR に追加する

#### 13. スコア表の本家準拠化

簡易式 100×n² をガイドライン準拠のスコア表に置き換える。

- 1/2/3/4 ライン = 100/300/500/800 × レベル (レベル制 #3 導入済みならレベルを乗算、未導入時はレベル 1 相当の固定値 ×1)
- ソフトドロップ +1/セル、ハードドロップ +2/セル
- T-スピン加点も本項に定義する: T-Spin Single/Double/Triple = 800/1200/1600 × レベル。有効化は #12 の判定実装が前提 (未実装の間は対象外)
- T-スピンと判定されたライン消去には基本ライン表の代わりに T-スピン表**のみ**を適用する (加算しない)
- 本項の要件範囲は上記の列挙 (基本ライン・ドロップ・T-スピン) が全てで、コンボ / Back-to-Back / Perfect Clear / T-Spin Mini は対象外

#### 14. キーコンフィグ

キー割り当てを変更できる。

- 全操作 (移動・回転・ドロップ・ホールド・ポーズ) のキーを変更できる設定 UI
- 設定を localStorage に保存し、重複割り当てを検出する
- デフォルトに戻すリセット操作を設ける

#### 15. DAS/ARR 調整

横移動の長押し挙動を調整可能にする。

- 現在の OS キーリピート依存をやめ、DAS (初回遅延) / ARR (連続間隔) をゲーム側で制御する
- 値を設定 UI から変更できる (既定値: DAS 170ms / ARR 50ms)

#### 16. モバイル対応

タッチ操作でプレイできるようにする。

- タップ/スワイプ操作 (左右スワイプ移動、タップ回転、下スワイプでドロップ等) を定義して実装する
- 画面幅に応じてセルサイズ・レイアウトが破綻しないレスポンシブ対応
- 既存のキーボード操作と共存する

#### 17. 色覚多様性対応

色だけに依存しない識別手段を提供する。

- 色覚多様性を考慮したパレットを選択できる (#9 のテーマ機構に載せる)
- ミノ種別を色以外 (模様・記号等) でも区別できる表示オプション

#### 18. リプレイ

直前のプレイを再生できる。

- プレイ中の入力 action 列と、再現に必要な出現情報 (シード可能な乱数のシード、または生成済みミノ列) を記録し、ゲームオーバー後に再生できる
- 再生中は入力を受け付けず、中断して新規ゲームを開始できる
- 保存は直近 1 プレイ分でよい (localStorage 永続化は任意)

#### 19. PWA 化

オフラインでも遊べるようにする。

- Web App Manifest + Service Worker を追加し、インストール可能にする
- オフラインで起動・プレイできる
- #11 (デプロイ) 済みの環境で動作確認する

#### 20. hook/component 層のテスト拡充

現在ロジック層のみのテストを UI 層へ広げる。

- useTetris の入力ガード (repeat / 世代判定 / over 中の Space 素通し) を自動テスト化する
- 主要 component の描画スモークテストを追加する
- 追加する各テストが「何のリグレッションを防ぐか」を説明できること (網羅カバレッジ目的の追加はしない)

## Launch Checklist (全機能共通の完了条件)

- [ ] `npm run build` (型チェック + ビルド) が通る
- [ ] `npm test` (vitest) が通る (既存テストの変更は、本 PRD が許可する挙動変更に伴う更新のみ)
- [ ] ロジックを追加・変更した場合、対応するユニットテストを同じ PR に含める
- [ ] ブラウザ実機でコアループ (落下・操作・消去・ゲームオーバー・Restart) と当該機能の要件項目を確認
- [ ] CI が green
- [ ] 既存挙動の変更 (スコア式・操作仕様等) は本 PRD に定義がある場合のみ
- [ ] 操作キーを追加した場合は README とゲーム内ヘルプ表示を更新

## 並列開発時の注意 (依存関係)

- 同一領域に触る組: #1×#3×#5×#6 (サイドパネル / スタッツ表示 — 上記 Mockups の配置合意に従う)、#9×#17 (パレット定義)、#14×#15 (入力設定)、#1×#18 (ミノ出現の決定性)、#3×#4 (useTetris の落下タイマー制御)。並列にする場合は事前にインターフェースを合意するか、直列にする
- #12 (SRS/ロックディレイ/T-スピン) は回転・固定の根幹を触るため、他のゲームプレイ系 (#1, #2, #3, #6) との同時進行は競合リスクが高い

## Open Questions
